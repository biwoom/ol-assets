# 붓다스토리 기획 구조안

## 1. 기획의 핵심 방향

**붓다스토리**는 부처님 일대기를 단순히 다시 서술하는 대용량 전기 콘텐츠가 아니라, 독자가 부처님의 생애를 **이야기 → 인물 → 톺아보기**의 흐름으로 따라가며 이해하고 기억하도록 설계된 웹 서사 콘텐츠입니다.

OL의 기존 콘텐츠 체계에서 STORY는 “불교의 인물·설화·가르침을 이야기 형식으로 재구성한 서사 콘텐츠”이고, TEXT는 경전·논서·강의록의 번역과 주석, DESIGN은 인포그래픽·삽화·스타일시트를 담당하는 영역으로 정리되어 있습니다.  또한 OL 브랜드 체계에서도 OL STORY는 서사 콘텐츠, OL TEXT는 문헌 콘텐츠, OL DESIGN은 시각 라이브러리로 구분되어 있습니다. 

따라서 붓다스토리는 다음 역할 분담을 따릅니다.

```txt
STORY  = 이야기의 흐름
ENTITY = 인물·장소·개념 등 지식 객체의 기준점
TEXT   = 심화 해설과 톺아보기
DESIGN = 시각 스타일과 삽화 제작 기준
```

이번 1차 기획에서는 **지역·주제·지도·관계그래프는 후순위**로 두고, 우선 **기본 서사 원고와 인물카드**에 집중합니다.

---

## 2. 독자의 기본 독서 구조

붓다스토리의 독서 흐름은 다음 순서가 되어야 합니다.

```txt
이야기 → 인물 → 톺아보기
```

### 1단계: 이야기

독자는 먼저 STORY 페이지에서 부처님 생애의 한 장면을 읽습니다.
이 단계의 핵심은 감동, 장면성, 인물의 내적 변화입니다.

### 2단계: 인물

본문 속 인물뱃지나 우측 인물카드를 통해 등장인물을 확인합니다.
인물카드는 단순한 프로필이 아니라, 독자가 인물을 기억하고 장면에 더 깊이 몰입하도록 돕는 장치입니다.

### 3단계: 톺아보기

더 깊은 교리적·학술적 이해가 필요한 독자는 TEXT 메뉴의 「붓다스토리 톺아보기」 문서로 이동합니다.
여기서 서사 본문에서 다루지 않은 원전, 전승 차이, 교리적 의미, 현대적 해석을 제공합니다.

이 구조는 OL이 지향하는 문사수 구조와도 잘 맞습니다. OL 브랜드 문서에서도 OL은 단순 지식 관리 시스템이 아니라, 불교 이야기를 읽고 듣는 문聞, 질문하고 사유하는 사思, 삶 속에서 체화하는 수修의 환경으로 설명됩니다.

## 3. STORY 페이지 기본 레이아웃

붓다스토리의 기본 페이지는 3단 구조로 설계합니다.

```txt
좌측: 여정
중앙: 이야기
우측: 인물
```

### 좌측: 여정

좌측은 단순 목차가 아니라 부처님 생애의 흐름을 보여주는 **여정 목록**입니다.

예:

```txt
Ⅰ. 태어남과 궁전
1. 탄생
2. 궁전과 네 가지 장면

Ⅱ. 떠남과 구도
3. 출가
4. 고행
5. 중도의 발견

Ⅲ. 깨달음과 전법
6. 깨달음
7. 첫 설법
8. 승가의 시작
```

좌측 영역의 역할은 “현재 내가 부처님 생애의 어느 지점을 읽고 있는가”를 알려주는 것입니다.

### 중앙: 이야기

중앙은 실제 서사 본문입니다.
이곳이 가장 중요합니다.

중앙 본문은 다음 원칙을 따릅니다.

```txt
짧은 단락
명확한 장면
감정의 흐름
교리의 자연스러운 삽입
과도한 학술 설명 배제
```

즉, STORY 본문은 논문도 강의록도 아닙니다.
부처님 생애의 사건을 따라가며 독자가 스스로 질문을 일으키게 하는 서사여야 합니다.

### 우측: 인물

우측에는 현재 회차 또는 현재 장면과 관련된 인물카드를 출력합니다.

우측 인물 영역의 역할은 다음과 같습니다.

```txt
현재 등장인물 확인
인물의 서사적 역할 기억
회차별 인물 상태 표시
인물 상세 페이지로 이동
```

## 4. 데스크탑과 모바일 동작 방식

### 데스크탑

데스크탑에서는 3단 레이아웃을 유지합니다.

```txt
좌측 여정 목록 고정
중앙 이야기 본문
우측 인물카드 출력
```

본문에서 인물뱃지를 클릭하면 우측 인물카드가 해당 인물로 교체되거나 강조됩니다.

예:

```md
싯다르타는 찬나와 함께 성문 밖으로 나갔다.

[[character:siddhattha]]
[[character:channa]]
```

이때 우측에는 싯다르타 또는 찬나 카드가 출력됩니다.

### 모바일

모바일에서는 우측 사이드바를 제거합니다.
본문 안의 인물뱃지를 클릭하면 인물카드가 팝업 모달로 열립니다.

```txt
본문 속 인물뱃지 클릭
→ 인물카드 모달 출력
→ 더 보기 클릭 시 ENTITY 인물 상세 페이지 이동
```

모바일에서는 카드가 본문 흐름을 방해하면 안 되므로, 본문 안에 큰 카드를 직접 삽입하기보다 **작은 인물뱃지 + 모달** 방식이 적합합니다.

## 5. 정보 구조의 핵심 원리

붓다스토리의 핵심 정보 구조는 다음과 같습니다.

```txt
STORY 원고
  ↓ 인물 id 참조

ENTITY 인물카드
  ↓ 시각자료 참조

DESIGN 스타일시트
```

이를 역할별로 정리하면 다음과 같습니다.

```txt
STORY  = 어떤 장면에서 어떻게 만나는가
ENTITY = 그 인물은 누구인가
DESIGN = 그 인물은 어떻게 보이고 기억되는가
TEXT   = 그 장면과 인물을 어떻게 깊이 이해할 것인가
```

즉, 인물카드의 원본 데이터는 ENTITY에 둡니다.
독자가 보는 인물카드 UI는 STORY 안에서 호출합니다.
시각 스타일과 삽화 제작 기준은 DESIGN에 둡니다.

이렇게 하면 인물카드가 단순 디자인 자산으로 축소되지 않고, 향후 관계망·검색·등장 회차·원전 연결의 기준점이 될 수 있습니다.

## 6. 메뉴별 역할 정리

## STORY

STORY는 독자가 실제로 읽는 붓다스토리 본편입니다.

담당 내용:

```txt
붓다스토리 본문
회차별 서사 원고
여정 목록
본문 인물뱃지
인물카드 호출
원전출처 부록 링크
톺아보기 링크
```

## ENTITY

ENTITY는 인물카드의 원본 데이터가 있는 곳입니다.

담당 내용:

```txt
인물의 기본 정보
이름 표기
기억 문장
서사적 역할
등장 회차
전승상 주의점
관련 시각 스타일시트 링크
```

현재 단계에서는 ENTITY를 공개 상단 메뉴로 노출하지 않아도 됩니다.
내부 데이터 경로 또는 숨은 라우트로 두고, STORY 페이지 안에서 호출하는 방식이 좋습니다.

## TEXT

TEXT는 「붓다스토리 톺아보기」 시리즈를 담당합니다.

담당 내용:

```txt
원전 비교
전승 차이
교리 해설
학술적 해설
심화 주제
부처님 생애의 사상적 의미
```

예:

```txt
네 가지 장면과 고성제
출가와 가족의 문제
고행과 중도
성도와 사성제
초전법륜의 의미
```

## DESIGN

DESIGN은 인물카드 자체가 아니라, 인물을 시각적으로 구현하기 위한 스타일시트와 삽화 기준을 담당합니다.

담당 내용:

```txt
인물 외형 기준
복식 기준
색상 팔레트
표정과 분위기
삽화 제작 프롬프트
장면별 이미지 톤
금지 표현
```

## 7. 폴더 구조 제안

사용자께서 제시한 구조를 기준으로 하되, STORY·ENTITY·TEXT·DESIGN의 역할을 반영하면 다음과 같이 정리할 수 있습니다.

```txt
src/content/
├── story/
│   └── buddha-story/
│       ├── index.md
│       ├── assets/
│       │   └── index.html
│       ├── appendix/
│       │   └── sources.md
│       ├── part-1/
│       │   ├── 01-birth.md
│       │   ├── 02-palace-and-four-sights.md
│       │   └── 03-renunciation.md
│       └── part-2/
│           ├── 01-awakening.md
│           ├── 02-first-sermon.md
│           └── 03-community.md
│
├── entity/
│   └── characters/
│       ├── siddhattha.md
│       ├── yasodhara.md
│       ├── rahula.md
│       ├── channa.md
│       ├── mara.md
│       └── sujata.md
│
├── text/
│   └── buddha-story-deep-dive/
│       ├── index.md
│       ├── four-sights-and-dukkha.md
│       ├── renunciation-and-family.md
│       ├── austerity-and-middle-way.md
│       └── awakening-and-four-noble-truths.md
│
└── design/
    └── character-style-sheets/
        ├── siddhattha-style.md
        ├── yasodhara-style.md
        ├── channa-style.md
        └── mara-style.md
```

이미지 파일은 `public/assets/` 또는 현재 프로젝트 자산 정책에 맞는 별도 경로에 둡니다.

```txt
public/assets/story/buddha-story/
├── characters/
│   ├── siddhattha/
│   ├── yasodhara/
│   ├── channa/
│   └── mara/
└── episodes/
    ├── birth/
    ├── four-sights/
    └── awakening/
```

## 8. STORY 원고 YAML 최소 구조

STORY 원고의 YAML은 복잡하면 안 됩니다.
처음에는 “이 회차가 무엇이고, 어떤 인물을 호출하고, 어디로 더 깊이 들어갈 수 있는가”만 관리하면 충분합니다.

```yaml
---
id: buddha-story-001-02
title: "궁전과 네 가지 장면"
series: buddha-story
part: 1
order: 2

layout: story-three-column

nav:
  prev: "/story/buddha-story/part-1/01-birth/"
  next: "/story/buddha-story/part-1/03-renunciation/"

characters:
  - id: siddhattha
    role: "주인공"
    display: featured
    state: "삶의 불안을 처음 마주함"

  - id: channa
    role: "동행자"
    display: compact
    state: "왕자의 질문을 곁에서 듣는 사람"

  - id: old-man
    role: "상징적 만남"
    display: symbolic
    state: "늙음의 진실을 드러냄"

deep_dive:
  title: "네 가지 장면과 고성제"
  url: "/text/buddha-story-deep-dive/four-sights-and-dukkha/"

sources:
  appendix: "/story/buddha-story/appendix/sources/"
  note: "여러 불전 전승을 바탕으로 재구성한 이야기입니다."
---
```

### 원리

```txt
id       = 이 문서의 고유값
title    = 독자에게 보이는 제목
part     = 여정 구조
order    = 정렬 순서
layout   = 3단 레이아웃 지정
nav      = 이전/다음 회차
characters = 이 회차에서 호출할 인물 id
deep_dive  = TEXT 톺아보기 연결
sources    = 원전출처 부록 연결
```

여기서 `characters.id`는 ENTITY의 인물 문서 id와 일치해야 합니다.

## 9. STORY 본문 작성 방식

STORY 본문은 일반 Markdown 서사로 작성하되, 인물 호출을 위한 간단한 표식을 넣습니다.

예:

```md
# 궁전과 네 가지 장면

싯다르타는 찬나와 함께 성문 밖으로 나갔다.  
그날 그가 본 것은 낯선 풍경이 아니었다.  
그것은 모든 사람이 이미 살고 있었지만, 그만은 아직 보지 못했던 삶의 진실이었다.

[[character:siddhattha]]
[[character:channa]]

## 첫 번째 만남

그는 한 노인을 보았다.  
등은 굽어 있었고, 걸음은 흔들렸으며, 얼굴에는 긴 시간이 남긴 주름이 깊었다.

[[character:old-man]]

싯다르타가 물었다.

“저 사람은 왜 저렇게 되었느냐?”

찬나가 대답했다.

“왕자님, 저것은 늙음입니다. 누구도 피할 수 없습니다.”
```

이때 본문 안의 `[[character:siddhattha]]`는 실제 출력 시 다음처럼 작동합니다.

```txt
데스크탑: 우측 인물카드 영역에 싯다르타 카드 표시
모바일: 본문에 싯다르타 뱃지 표시, 클릭 시 모달 출력
```

## 10. ENTITY 인물카드 YAML 최소 구조

ENTITY 문서는 인물의 기준 데이터입니다.
여기에는 회차별 감정 상태보다 **인물 자체의 고정 정보**를 둡니다.

```yaml
---
id: siddhattha
type: character

name:
  ko: "싯다르타"
  pali: "Siddhattha"
  sanskrit: "Siddhārtha"

memory_phrase: "고통을 외면하지 못한 사람"

summary: "부처님이 되기 전의 고타마. 궁전의 삶 속에서도 늙음과 병듦과 죽음의 문제를 외면하지 못하고 구도의 길로 나아간 인물."

story_role: "부처님 생애 서사의 중심 인물"

appears_in:
  - "/story/buddha-story/part-1/02-palace-and-four-sights/"
  - "/story/buddha-story/part-1/03-renunciation/"
  - "/story/buddha-story/part-2/01-awakening/"

design:
  style_sheet: "/design/character-style-sheets/siddhattha-style/"
  image: "/assets/story/buddha-story/characters/siddhattha/main.webp"
---
```

### 원리

```txt
id              = STORY 원고에서 참조하는 인물 id
name            = 이름 표기
memory_phrase   = 독자가 기억할 한 문장
summary         = 인물 설명
story_role      = 붓다스토리 안에서의 역할
appears_in      = 등장 회차
design          = DESIGN 스타일시트와 대표 이미지 연결
```

중요한 점은 `memory_phrase`입니다.
인물카드는 정보보다 기억이 먼저입니다.

예:

```txt
싯다르타: 고통을 외면하지 못한 사람
야소다라: 떠난 이의 뒤에 남겨진 사람
라훌라: 사랑과 집착의 이름을 함께 가진 아이
아난다: 가장 가까이에서 듣고, 가장 오래 기억한 제자
마라: 두려움과 집착이 얼굴을 얻은 존재
```

## 11. DESIGN 스타일시트 YAML 최소 구조

DESIGN 문서는 시각 기준입니다.
인물의 교리적·서사적 설명이 아니라, 이미지와 카드 UI를 일관되게 만들기 위한 기준입니다.

```yaml
---
id: siddhattha-style
target_entity: siddhattha
type: character-style-sheet

visual_identity:
  age_range: "청년기"
  expression: "고요하지만 깊이 질문하는 얼굴"
  costume: "고대 인도 왕실 복식"
  atmosphere: "절제된 왕실의 고요함과 내적 불안"

palette:
  - muted gold
  - ivory
  - deep brown

avoid:
  - 과도한 신성화
  - 현대 판타지풍 갑옷
  - 지나친 영웅화
  - 과장된 표정
---
```

### 원리

```txt
target_entity = 어떤 ENTITY 인물에 대한 스타일인지
visual_identity = 외형·표정·복식·분위기
palette = 반복 사용할 색감
avoid = 피해야 할 표현
```

## 12. TEXT 톺아보기 YAML 최소 구조

TEXT의 「붓다스토리 톺아보기」는 STORY의 서사 흐름을 방해하지 않고, 더 깊은 이해를 원하는 독자를 위한 별도 문서입니다.

```yaml
---
id: four-sights-and-dukkha
title: "네 가지 장면과 고성제"
series: buddha-story-deep-dive
related_story:
  - "/story/buddha-story/part-1/02-palace-and-four-sights/"

topics:
  - "고성제"
  - "무상"
  - "출가의 동기"

source_level: "introductory"
---
```

### 원리

```txt
related_story = 연결되는 STORY 회차
topics        = 이 문서가 다루는 주제
source_level  = 입문/중급/전문 수준 표시
```

TEXT 톺아보기는 처음부터 논문처럼 길 필요는 없습니다.
처음에는 STORY에서 설명하지 않은 내용을 보충하는 짧은 해설문으로 시작하고, 나중에 원전 비교·주석·참고문헌을 확장하면 됩니다.

## 13. 원전출처 부록 문서 구조

원전출처는 STORY 각 회차마다 길게 넣지 않고, 「붓다스토리 부록: 원전과 전승」 같은 총괄 문서에서 관리합니다.

경로 예:

```txt
src/content/story/buddha-story/appendix/sources.md
```

이 문서는 다음 역할을 합니다.

```txt
붓다스토리 전체가 참조하는 원전 목록
전승 층위 구분
초기불교 자료
율장 자료
불전문학 자료
대승 전기류
한역 불전 자료
현대 연구 참고문헌
저작권·번역 이용 주의사항
```

각 STORY 회차 하단에는 짧게만 표시합니다.

```txt
이 이야기는 여러 불전 전승을 바탕으로 재구성했습니다.
자세한 원전과 전승 구분은 「붓다스토리 원전과 전승」을 참고하세요.
```

## 14. 인물카드 UI의 원칙

인물카드는 독자가 인물을 기억하도록 돕는 장치입니다.
정보량이 너무 많으면 안 됩니다.

### STORY 우측 인물카드 기본 구성

```txt
대표 이미지
이름
기억 문장
짧은 설명
이 장면에서의 역할
더 보기
```

예:

```txt
싯다르타

고통을 외면하지 못한 사람.

궁전의 삶 속에서도 늙음과 병듦과 죽음의 문제를 외면하지 못하고 구도의 길로 나아간 인물.

이 장면에서:
처음으로 삶의 불안을 마주한다.

더 보기 →
```

여기서 “이 장면에서”는 STORY 원고 YAML의 `state` 값을 사용합니다.
인물의 고정 설명은 ENTITY에서 가져오고, 회차별 상태는 STORY YAML에서 가져옵니다.

## 15. 전체 구조의 핵심 원리

최종 원리는 다음 한 문장으로 정리할 수 있습니다.

> **STORY는 인물을 장면 속에서 만나게 하고, ENTITY는 그 인물이 누구인지 기억하게 하며, DESIGN은 그 인물이 어떻게 보일지 통일하고, TEXT는 그 장면의 의미를 깊게 해설한다.**

조금 더 압축하면 다음과 같습니다.

```txt
STORY  = 만남
ENTITY = 기억
DESIGN = 형상
TEXT   = 이해
```

## 16. 우선 제작 순서

처음부터 모든 구조를 완성하려고 하면 무거워집니다.
다음 순서가 가장 현실적입니다.

```txt
1. STORY 붓다스토리 index.md 작성
2. part-1 회차 2~3개 작성
3. 핵심 인물 ENTITY 카드 5개 작성
4. 인물카드 UI 컴포넌트 설계
5. 모바일 인물 모달 설계
6. TEXT 톺아보기 문서 1~2개 작성
7. 원전출처 부록 sources.md 작성
8. DESIGN 스타일시트 2~3개 작성
```

처음 제작할 인물은 다음 정도면 충분합니다.

```txt
싯다르타
야소다라
라훌라
찬나
마라
```

처음 제작할 STORY 회차는 다음 정도가 좋습니다.

```txt
1. 탄생
2. 궁전과 네 가지 장면
3. 출가
```

처음 제작할 TEXT 톺아보기는 다음이 좋습니다.

```txt
네 가지 장면과 고성제
출가와 가족의 문제
```

## 17. 최종 정리

붓다스토리는 다음 구조로 잡는 것이 가장 좋습니다.

```txt
독서 흐름:
이야기 → 인물 → 톺아보기

페이지 구조:
좌측: 여정
중앙: 이야기
우측: 인물

데이터 구조:
STORY 원고
  ↓ 인물 id 참조
ENTITY 인물카드
  ↓ 시각자료 참조
DESIGN 스타일시트

심화 구조:
STORY 본문
  ↓
TEXT 붓다스토리 톺아보기

출처 구조:
각 회차에는 짧은 출처 안내
상세 출처는 STORY 부록 sources.md에서 총괄
```

이 구조의 장점은 분명합니다.

첫째, STORY 본문이 무거워지지 않습니다.
둘째, 인물카드가 단순 장식이 아니라 기억 장치가 됩니다.
셋째, TEXT 톺아보기로 학술적 깊이를 확보할 수 있습니다.
넷째, DESIGN 스타일시트로 삽화와 카드의 시각적 일관성을 유지할 수 있습니다.
다섯째, 나중에 지역·주제·지도·관계그래프를 추가해도 기존 구조를 크게 바꾸지 않아도 됩니다.

결국 붓다스토리는 **“부처님 생애를 읽는 콘텐츠”**를 넘어, **“부처님 생애의 인물들을 만나고, 기억하고, 그 의미를 자기 삶으로 되돌아보는 웹 서사”**가 되어야 합니다.
